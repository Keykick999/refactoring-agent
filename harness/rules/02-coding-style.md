# Coding Style

## General

코드는 동작뿐만 아니라 읽기 쉬운 것을 중요하게 한다.

### Naming

- 변수와 메서드는 역할이 명확하게 드러나는 이름을 사용한다.
- 의미 없는 이름을 사용하지 않는다.
- 축약어를 과도하게 사용하지 않는다.

Bad:
- `data`
- `obj`
- `res`
- `doSomething()`

Good:
- `toolResult`
- `agentState`
- `executeTool()`

## Method

- 하나의 메서드가 너무 많은 책임을 갖지 않도록 한다.
- 메서드 이름만 읽어도 역할을 이해할 수 있어야 한다.
- 중첩 조건문을 과도하게 만들지 않는다.

## Class

- 클래스의 책임을 명확하게 유지한다.
- 거대한 클래스를 만들지 않는다.
- 관련 없는 기능을 하나의 클래스에 넣지 않는다.

## Comments

주석은 코드가 무엇을 하는지 반복해서 설명하기보다
왜 그렇게 구현했는지를 설명하는 데 사용한다.

불필요한 주석은 작성하지 않는다.

## Abstraction

추상화는 실제 필요성이 확인된 경우에만 추가한다.

미래 확장을 가정한 과도한 인터페이스나 패턴을 만들지 않는다.
